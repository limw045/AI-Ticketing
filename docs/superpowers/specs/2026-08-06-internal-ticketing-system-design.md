# Technical Design Specification: Internal Staff Ticketing Platform

**Date:** 2026-08-06  
**Status:** Approved  
**Deployment Target:** Vercel  

---

## 1. Overview & Objectives

The goal of this project is to build a modern, high-efficiency internal ticketing and communication platform for company staff (`@gtmsw.com.my`) and interns (`@outlook.com`) to report issues, request IT support, and track resolutions.

The platform combines developer-grade polish (GitHub/Linear inspired timeline & keyboard shortcuts), Markdown support, drag-and-drop clipboard image uploads, Microsoft Teams integration, a Pinned Q&A Knowledge Base, an Admin Analytics Dashboard, Global Outage Banners, External App API Log Ingestion, AI Assist (Summary & Draft Reply), and Sensitive Data Masking.

---

## 2. Technical Stack

* **Frontend & API**: Next.js 14+ (App Router, Server Actions, React Email)
* **Backend as a Service**: Supabase (PostgreSQL Database, Supabase Auth, Supabase Storage, Supabase Realtime)
* **Styling & UI**: Tailwind CSS, shadcn/ui, Recharts / Tremor (for Analytics charts), Zinc color palette, Geist Sans & Geist Mono typography
* **AI Engine**: Vercel AI SDK (OpenAI / Claude API for Ticket Summarization & Draft Reply Generation)
* **Integrations & Queue**: Microsoft Teams (Incoming Webhooks / Adaptive Cards), Resend/Nodemailer, Upstash Redis / Vercel Queue (for async Webhook retries & rate-limiting)
* **Hosting**: Vercel

## 3. Authentication, Domain Rules & API Ingestion

### 3.1 Domain & Role Rules
1. **Full-time Staff (`@gtmsw.com.my`)**
   - Automatically assigned `user_type: full_time`.
   - Requires department selection during registration.
2. **Interns & Contractors (`@outlook.com`)**
   - Automatically assigned `user_type: intern`.
   - Requires department selection + supervisor name during registration.
3. **Account Migration Handling**: Supporting email/domain migration (e.g., Intern converting to Full-time staff) via Supabase Auth admin API while maintaining foreign key integrity (`author_id`).
4. **Other Public Domains (`@gmail.com`, `@qq.com`, etc.)**
   - Strictly rejected at authentication/registration API level.

### 3.2 User Roles (`profiles.role`)
- `employee`: Standard ticket creator. Can view/comment on own tickets and browse Pinned Q&A.
- `support_agent`: IT / Support staff. Can be assigned tickets, change statuses, post internal notes, use bulk actions, and manage FAQs.
- `admin`: Full administrative access to manage users, labels, categories, FAQ pinning, outage banners, and view the Analytics Dashboard.

### 3.3 External App Integration (`/api/v1/tickets`)
Internal applications can submit tickets programmatically via API Key authentication:
- Accepts JSON payload with `title`, `description`, `category`, `user_email`, and `system_logs` (error stack trace, app version, runtime state).
- **Payload Truncation & Sanitization Middleware**: Maximum 50KB payload limit for `system_logs` to prevent DB bloat/crashes.
- **Rate-Limiting**: Max 60 requests/min per API Key to prevent loop spam from external apps.

## 4. Database Schema (PostgreSQL via Supabase)

| Column | Type | Constraints / Description |
|---|---|---|
| `id` | UUID | PRIMARY KEY, REFERENCES `auth.users(id)` ON DELETE CASCADE |
| `email` | TEXT | UNIQUE, NOT NULL |
| `display_name` | TEXT | NOT NULL |
| `user_type` | TEXT | ENUM: `'full_time'`, `'intern'`, `'contractor'` |
| `department` | TEXT | NOT NULL (e.g., `'IT'`, `'HR'`, `'Marketing'`, `'Finance'`) |

| `avatar_url` | TEXT | NULLABLE |
| `created_at` | TIMESTAMPTZ | DEFAULT `now()` |

| Column | Type | Constraints / Description |
|---|---|---|
| `id` | UUID | PRIMARY KEY, DEFAULT `gen_random_uuid()` |

| `is_pinned` | BOOLEAN | DEFAULT `false` (Used for Pinned Q&A / Knowledge Base) |
| `pin_order` | INT | DEFAULT `0` |
| `device_context` | JSONB | NULLABLE (Browser, OS, URL, Screen Resolution, IP) |
| `system_logs` | TEXT / JSONB | NULLABLE (Error stack traces & app logs from API ingestion) |
| `ai_summary` | TEXT | NULLABLE (1-sentence summary generated by AI) |
| `first_responded_at`| TIMESTAMPTZ | NULLABLE (For SLA response calculation) |
| `resolved_at` | TIMESTAMPTZ | NULLABLE (For SLA resolution calculation) |
| `deleted_at` | TIMESTAMPTZ | NULLABLE (Soft delete for spam/accidental creation) |

## 5. Submitter (User) Experience & Frontend Resilience

### 5.1 Form Draft Auto-Save (`localStorage`)
- Auto-saves form input fields (`title`, `description`, `category`) to browser `localStorage` in real time.
- Restores draft automatically if page crashes, network drops, or tab is accidentally closed.

### 5.2 Client-Side Image Compression & Upload Progress
- Image files selected/pasted via `Ctrl+V` are automatically compressed on the client using HTML5 Canvas / `browser-image-compression` before upload.
- Upload progress bar shown inline in the Markdown editor.

### 5.3 Realtime Status Updates (Supabase Realtime)
- Ticket detail page (`/tickets/[id]`) subscribes to WebSocket updates via Supabase Realtime.
- Staff see new IT replies and status changes appear live without manually refreshing the page.

---

## 6. Support Agent & Maintenance Resilience (Underlying Architecture)

### 6.1 Realtime Presence & Optimistic Concurrency Control
- Displays **"Agent X is currently viewing/editing this ticket"** badge in the sidebar using Supabase Realtime Presence.
- Prevents race conditions when two agents try to process the same ticket concurrently.

### 6.2 Immutable System Audit Logs
- State modifications (Status changes, Assignee updates, Priority adjustments) trigger automatic records in `ticket_audit_logs`.
- Displayed inline in the ticket timeline as system events (e.g., *"Alex updated status from Open to In Progress (10 mins ago)"*).

### 6.3 Asynchronous Webhook Queue & Retries
- Teams Webhook calls are processed asynchronously via Next.js `after()` or Vercel background workers.
- If Microsoft Teams Webhook fails or is rate-limited, the system retries up to 3 times without blocking or failing the user's ticket creation request.

### 6.4 Soft Delete Strategy
- Tickets marked as deleted/spam set `deleted_at = now()`.
- Excluded from standard queries while preserving comment relationships and foreign key integrity.

## 8. Notifications & Webhook Flow

1. **Ticket Created**:
   - Post Microsoft Teams **Adaptive Card** with AI-generated summary to IT support channel asynchronously.
   - Send confirmation email to ticket author.
2. **Ticket Status Change / Reply**:
   - Send notification email to author with direct link to ticket timeline.

## 9. Security & Row Level Security (RLS)

- **`profiles`**: Users can read all profiles; users can only update their own profile.
- **`tickets`**: Employees can read their own created tickets (`author_id = auth.uid()`). Support agents/admins can read/edit all tickets.
- **`comments`**: Non-agent employees CANNOT query rows where `is_internal_note = true`.
- **`ticket_audit_logs`**: Read-only for authenticated users; insert-only via database triggers/server actions.
- **`faqs`**: Publicly readable; writable by `admin` and `support_agent`.
- **`incidents`**: Publicly readable; writable only by `admin`.
- **API Keys & Webhooks**: Hashed authentication keys for external app log submissions (`/api/v1/tickets`).
